> 最近两天，我对“毛坯房”状态的 OpenAdServer 进行了深度填坑。从最初重构回 Node.js 时只支持单一的 CPM 模式，到现在，依托于 PulseSim 模拟器的持续鞭策以及 pCTR 和 pCVR 模型的成功训练，我终于让引擎顺利上马了 CPC、CPA 甚至 oCPM！不仅在排序侧引入了广义第二价格（GSP）机制，我还在底层将预估分值打入了广告流日志。今天，就来盘点一下这次从“大锅饭”到“效果为王”的架构升级，顺便聊聊在广告主、媒体和平台眼中，这四种计费模式背后的利益博弈。

## 1. 铺垫：打磨 PulseSim 与模型的诞生

之前，我的 OpenAdServer 只有一个可怜的 CPM Campaign，为了让系统真正运转起来，我花了大量时间调整流量模拟器 **PulseSim**。

我为模拟器增加了几个固定的 `slot_id`（广告位），并给不同位置强行绑定了点击和转化率的加成逻辑。这样不仅模拟了真实世界中“首页 Banner 效果优于页脚”的物理规律，也让数据呈现出明显的区分度。

借着这些稍微优质了一点的数据，我开始了特征工程的迭代博弈：
* **Sparse vs Dense**：期间我进行了多轮尝试。最典型的一个改动就是，我舍弃了直接将 `banner_width` 和 `banner_height` 作为 Dense 连续特征，而是将它们拼接成了单一的 `size` 字符串（例如 `320x50`），并挪编进了 Sparse 离散特征组来做 Embedding。
* **复用 BigQuery**：在特征拉取阶段，我采用了一次查询拉取全部样本特征再过滤的策略，大幅降低了查询延迟。

一套组合拳下来，训练出的 DeepFM 模型中有了质的飞跃：**模型明确识别到了位置加成特征！** 在验证集里，输出的点击和转化预测比例终于进入了一个合乎商业逻辑的“可接受”区间。

## 2. 算法驱动业务：四种计费模式与 GSP 的落地

当系统同时拥有了可用的 **pCTR（预估点击率）** 和 **pCVR（预估转化率）** 后，业务侧也就迎来了大爆发。“纯展示”时代结束了。

在 `ranking.service.ts` 的排序逻辑中，我补排了一整套的计费推算（eCPM转化）：

* **CPM**: $eCPM = Bid$
* **CPC**: $eCPM = Bid \times pCTR \times 1000$
* **CPA / oCPM**: $eCPM = Bid \times pCTR \times pCVR \times 1000$

为了保证广告主利益最大化，不让他们因为出价虚高而破产，我顺手实现了 **GSP（广义第二价格）** 扣费机制。排序第一的广告主，只需要出排名第二的广告主所对应的 eCPM 价格即可：

```typescript
// GSP 收费核心逻辑
const nextEcpm = (i + 1 < sorted.length) ? (sorted[i + 1].score || 0) : 0;
let requiredBid = 0;

if (c.bid_type === BidType.CPC) {
    requiredBid = nextEcpm / (pctr * 1000);
} else if (c.bid_type === BidType.CPA || c.bid_type === BidType.OCPM) {
    requiredBid = nextEcpm / (pctr * pcvr * 1000);
}

// 实际扣费卡在 0.01 保底，同时不超过广告主的出价上限
c.actual_cost = Math.min(c.bid, Math.max(0.01, requiredBid));
```

## 3. 商业博弈论：CPM、CPC、CPA 与 oCPM

顺便科普一下我在写这套竞价逻辑时，关于这四种模式的思考。在 AdTech 生态中，有三个核心角色：**Advertiser（广告主）、Publisher（媒体/流量方）和 Ad Platform（广告平台/引擎）**。计费模式本质上是对“风险”的转移。

### 1️⃣ CPM (Cost Per Mille) - 按千次展示付费
* **逻辑**：只要广告展现出来了就得给钱。
* **视角**：
  * **媒体**：最喜欢。无风险收租模式，流量就是地段，展示了就给钱。
  * **广告主**：高风险。如果素材烂没人点，钱就白砸了。
  * **平台**：技术难度最低，不需要算 pCTR/pCVR。这属于早期古典互联网的粗暴玩法。

### 2️⃣ CPC (Cost Per Click) - 按点击付费
* **逻辑**：只有用户点击了广告，才需要扣钱。
* **视角**：
  * **媒体**：有点慌了，万一推了一个没人点的广告，白白浪费了展示位（无收入）。为了盈利，媒体必须疯狂压榨点击率高的广告。
  * **广告主**：稍微放心了，只为“意向人群”买单。但如果点完不买（转化差），还是亏。
  * **平台**：必须依赖极强的 **pCTR 预估模型**，确保展示那些高点击率的内容，不然平台没钱赚。

### 3️⃣ CPA (Cost Per Action) - 按转化付费
* **逻辑**：用户得下载、注册甚至购买，广告主才掏钱。
* **视角**：
  * **广告主**：最舒服，这就是纯正的“保本效果广告/ROI 承诺”。
  * **媒体**：坚决抵制。凭啥我要为你的商品没吸引力或者注册链路太长负责？
  * **平台**：技术难度极高。全链路数据不可控，极易被“薅羊毛”。目前市面上纯正的 CPA 其实很少见。

### 4️⃣ oCPM (Optimized CPM) - 平台利益的终极武器
* **逻辑**：**按 CPM（展示）扣费，但平台通过算法自动按 CPA（转化目标）帮你优化展示人群。**
* **视角**：这是当今大媒体平台（抖音巨量、腾讯广点通、Facebook）的绝对主力兵种。
  * **广告主**：只需要设置“我期望获取一个用户的最高成本(CPA Bid)”，剩下的大模型搞定。成本可控，省心。
  * **媒体**：还是按展示收到了钱，保底了流量价值。
  * **平台**：赢麻了。把算法壁垒化为利润。引擎不仅利用 **pCTR + pCVR** 准确定位高转化人群，还在流量充足时进行溢价售卖。谁的数据多，谁的大模型强，谁就能通吃市场。

## 4. 兜底策略与数据飞轮

系统升级后，新的挑战随之而来：如果新建的 Campaign 没有数据，pCTR 预估分极低，根本拿不到流量怎么办？
于是，我配置了一个 **Evergreen (常青树) Campaign**。这是一个纯展示类的底部打底广告，无论竞争多激烈，它永远以微弱的价格来吸收那些没人要的残余流量，保证广告位永远不空窗。

同时，这部分请求也被合理分发到了 PulseSim。

更关键的一点是，为了让算法越用越强，我在此次提交中将预测阶段获取的 `pctr` 和 `pcvr` 数据一同反写注入到了底层的 `ad_events` 日志表中。
**所谓的数据飞轮，正式启动。** 模型在 serving 时的每一个预估结果，都会成为后续离线校验和 Loss 惩罚的基石。

目前优化过脉冲模拟器后，系统内完整连贯的多维度数据只有不到两天。我已经迫不及待地想看几天之后，当数据池膨胀到一个新量级，我这套“初具雏形”的引擎训练出来的新模型，能不能在接下来的自动化竞价里打出一场漂亮仗了。
